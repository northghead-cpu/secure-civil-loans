# Automatic financial document analysis

The queue is refreshed when KYC documents or lender handoff authorisations change. A private database trigger wakes a user-targeted, cron-authenticated Edge worker immediately after document, OCR metadata, profile or handoff changes commit. One wake per user per transaction batches multi-document uploads; the minute cron remains the retry/recovery path. Network failures never roll back uploads. PENDING and VALID private documents can populate a private preliminary snapshot; lender summaries are independently selected from VALID documents only. PDF hashes and document IDs identify all evidence. GRZ payroll totals, period and employee identity must match before figures are used. Zanaco direct debits and unpaid reversals remain distinct; repeated statements are deduplicated. Possible same-creditor payroll overlaps are excluded from the external-debt lower bound and flagged rather than silently counted twice.

The document debt ratio uses identified payroll debt plus the non-overlapping bank-debt lower bound and proposed repayment over gross salary. It is provisional, not a lender-confirmed DTI or credit decision. Recognised living-cost transactions may produce a monthly estimate only with at least 28 days of activity and no unclassified spending; transfers and withdrawals are never assumed to be living costs. Missing/unsupported evidence remains explicitly unknown, never a confirmed zero.

Results sync through a domain-separated timestamped HMAC endpoint to an existing tenant-bound Handshake referral only where financial information sharing is authorised. Existing signed handoffs must include income, verification results and supporting documents. Manual owner attestations require an explicit financial-assessment audit record. Full PDF text, account numbers, NRC and employee numbers do not enter Slack or the summary payload. Staff-reviewed assessment inputs are preserved. Extraction quality is a transparent parser-check count, not a diligence/credit score.

Deploy the analysis migrations and Edge functions before enabling supabase/operations/enable-financial-document-analysis.sql. The worker uses the existing private cron secret, Supabase service credentials and dedicated FINANCIAL_ASSESSMENT_HMAC_SECRET on both projects and FINANCIAL_ASSESSMENT_TENANT_MAP where lender aliases need mapping. No paid API, browser task or VPS is required. All substantive lender checks and separate KYC release gates remain intact.

Staff can inspect Automatic financial analysis in Admin → KYC → Review evidence. The MFA-protected summary RPC omits raw text and bank references, and hides results from stale generations while reanalysis is pending. The panel polls while open and marks pending-document figures as preliminary. The server independently reads source PDFs; client OCR text is not accepted as trusted financial evidence. Browser OCR alone, before the upload is saved, does not trigger server analysis. Image-only PDFs and image OCR results are not yet supported by the server financial parser and remain unreadable/unknown rather than inferred.
