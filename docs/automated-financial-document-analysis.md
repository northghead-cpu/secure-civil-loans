# Automatic financial document analysis

The queue is refreshed when KYC documents or lender handoff authorisations change. A cron-authenticated Edge worker processes one leased job per minute, using only VALID private documents owned by the source user. PDF hashes and document IDs identify all evidence. GRZ payroll totals, period and employee identity must match before figures are used. Zanaco direct debits and unpaid reversals remain distinct; repeated statements are deduplicated. Possible same-creditor payroll overlaps are excluded from the external-debt lower bound and flagged rather than silently counted twice.

The document debt ratio uses identified payroll debt plus the non-overlapping bank-debt lower bound and proposed repayment over gross salary. It is provisional, not a lender-confirmed DTI or credit decision. Recognised living-cost transactions may produce a monthly estimate only with at least 28 days of activity and no unclassified spending; transfers and withdrawals are never assumed to be living costs. Missing/unsupported evidence remains explicitly unknown, never a confirmed zero.

Results sync through a domain-separated timestamped HMAC endpoint to an existing tenant-bound Handshake referral only where financial information sharing is authorised. Existing signed handoffs must include income, verification results and supporting documents. Manual owner attestations require an explicit financial-assessment audit record. Full PDF text, account numbers, NRC and employee numbers do not enter Slack or the summary payload. Staff-reviewed assessment inputs are preserved. Extraction quality is a transparent parser-check count, not a diligence/credit score.

Deploy both migrations and Edge functions before enabling supabase/operations/enable-financial-document-analysis.sql. The worker uses the existing private cron secret, Supabase service credentials and referral HMAC configuration. No paid API, browser task or VPS is required. All substantive lender checks and separate KYC release gates remain intact.
